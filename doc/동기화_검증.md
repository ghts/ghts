# TR 필드 동기화·검증 작업 지침

> `type_c.h`(C 헤더, 필드별 한글 주석 있음)와 `tr_*.go`(Go TR 변환 코드)의 필드 매핑을
> 대조하여, **역할이 다른 필드에서 값을 가져오는 잘못된 복사 오류**를 찾아내는 반복 작업의 절차서.
> 동일 방식을 반복해서 수행할 수 있도록 기록한다.

---

## 1. 목적

- `tr_*.go` 각 변환 함수가 `type_c.go`(C 구조체)의 어느 필드에서 값을 읽어 Go 구조체 필드에
  복사하는지 전수 확인
- 주석 의미와 다른 필드에서 값을 가져오는 오류(복착·복붙 오류) 발견
- 발견된 결함은 `버그_리포트.md`에 등재, 해결 확인 항목은 삭제

## 2. 배경 지식 (이 작업의 핵심)

세 파일의 관계와 필드명 규칙을 알지 못하면 잘못된 "오류"를 다수 착시한다.

| 파일 | 용도 | 필드명 규칙 | 주석 |
|---|---|---|---|
| `xing/base/type_c.h` | C 전용 PACKED 구조체 | **소문자** (`high`, `opentime`) | 필드별 한글 주석 있음 |
| `xing/base/type_c.go` | `go tool cgo -godefs`로 생성된 UNPACKED 구조체 | **첫 글자 대문자** (`High`, `Opentime`) | 주석 없음 |
| `xing/base/tr_*.go` | C→Go / Go→C 변환 코드 | `type_c.go` 필드명 사용 (대문자) | — |

**가장 중요한 규칙**: `tr_*.go`가 쓰는 필드명은 `type_c.go`(cgo 결과)의 **대문자** 이름이고,
`type_c.h` 주석은 **소문자** 이름에 붙어 있다. 따라서 대조는
**첫 글자를 소문자로 낮춰 비교**(case-insensitive)해야 한다.
직접 대소문자를 맞추지 않으면 `High`→`high` 불일치로 오류를 "미등록 필드"로 잘못 분류한다.

### InBlock / OutBlock 방향
- `InBlock`: Go 질의값 → C 구조체 (`lb.F바이트_복사_(g.필드[:], 질의값.M...)`)
- `OutBlock`: C 구조체 → Go 응답 (`s.M필드 = ... g.필드 ...`)
- InBlock/OutBlock은 증권사 API의 질의·응답 방향일 뿐, C↔Go 데이터 방향과 무관함.
  검증 로직은 양 방향 모두 동일하게 적용한다.

## 3. 검토 대상 파일

```
xing/base/type_c.h          # C 헤더 (필드별 주석 원본)
xing/base/type_c.go         # cgo 생성 Go 구조체 (필드명의 실제 대소문자)
xing/base/tr_*.go           # 변환 코드 (총 29개)
```

## 4. 작업 절차

### 4.1 파일 준비 (Python 샌드박스 스테이)
Python 실행 환경은 호스트 파일을 직접 읽을 수 없어, **먼저 tar로 묶어 한 파일로 가져와야** 한다.
1회 스테이 최대 20개 파일이므로, 20개를 초과하면 tar로 압축한다.

```bash
cd github.com/ghts/ghts/xing/base
tar -czf /tmp/tr_files.tar.gz type_c.h type_c.go tr_*.go
```

### 4.2 type_c.h 파싱 (구조체 소속 정리 + 필드→주석)
- **오프바이원 주의**: `type_c.h`는 `} 이름;`이 구조체 본문 **뒤**에 온다.
  필드를 즉시 소속 구조체에 넣으면 하나 어긋난다. `} 이름;`을 만났을 때 버퍼에 쌓아둔
  필드를 그 이름에 플러시(flush)하는 방식으로 소속을 정리한다.
- 필드명은 소문자 키로 저장해 후대 대조 작업을 편하게 한다.

### 4.3 tr_*.go 매핑 추출
- **OutBlock**: `s.M<Go필드> ... g.<C필드>` (문장 경계 `; { }`까지, `, 에러 =` 허용)
- **InBlock**: `g.<C필드>[:], ... M<Go필드>` (같은 줄에서 마지막 `M<Go필드>` 채택)
- 중첩 구조체(`M응답1`, `M반복값_모음`, `M헤더…` 등)는 제외

### 4.4 대조
- OutBlock/InBlock 각각 `g.<C필드>`의 주석을 소문자 조회로 얻어, Go 필드명과 나란히 정렬
- 한글 bigram 유사도(Dice)를 산출해 의심 후보(낮은 점수) 우선 검토

### 4.5 판정
- 유사도 점수만 믿지 않고, **실제 `tr_*.go` 소스코드를 직접 열어** 확인한다.

## 5. 완전 재실행 스크립트

아래 스크립트를 `type_c.h`, `type_c.go`, `tr_*.go`를 스테이한 후 실행하면
전체 매핑 테이블과 유사도 결과를 얻는다. (환경별 스테이 경로는 실제 환경에 맞출 것)

```python
import tarfile, os, glob, re
from collections import defaultdict

# -- 1) type_c.h 파싱 (구조체 소속 정리 + 소문자 필드->주석) --
hcomment_global = {}
cur = None; buf = []
for raw in open("/inputs/type_c.h", encoding="utf-8"):
    raw = raw.rstrip("\n")
    m = re.match(r"\}\s*([A-Za-z_]\w*)\s*;", raw)
    if m:                                   # } 이름;  -> 버퍼 플러시
        cur = m.group(1)
        for f, c in buf: hcomment_global[f.lower()] = c
        buf = []; continue
    fm = re.match(r"\s*(?:typedef\s+)?(?:struct\s+)?[A-Za-z_][\w<>\*\s]*?\s+(\w+)\s+\[\s*\d+\s*\]\s*;", raw)
    if fm and cur is not None:
        field = fm.group(1); comment = ""; ci = raw.find("//")
        if ci != -1:
            ct = raw[ci+2:]
            tm = re.match(r"\s*\[[^\]]*\]\s*(.*)", ct, re.S)
            if tm: ct = tm.group(1)
            sm = re.search(r"\s+StartPos\b.*", ct)
            if sm: ct = ct[:sm.start()]
            comment = ct.strip()
        buf.append((field, comment))

cmt = lambda g: hcomment_global.get(g.lower(), "??없음??")   # 소문자 비교 핵심

# -- 2) tr_*.go 매핑 추출 --
files = sorted(glob.glob("/inputs/tr_*.go"))
KOR = r"[가-힣0-9_]+"
re_out = re.compile(r'\bs\.M(' + KOR + r')\b[^;{}]*?\bg\.([A-Za-z_]\w*)')
re_in  = re.compile(r'\bg\.([A-Za-z_]\w*)\[\:\]')
re_new = re.compile(r'\bg\s*:=\s*new\((\w+)')
re_func = re.compile(r'^func\s+([A-Za-z_]\w*)\s*\(', re.M)
NESTED = {"M응답1","M응답2","M반복값_모음","M헤더1","M헤더2","M헤더","M모음"}
allm = []
for path in files:
    name = os.path.basename(path); text = open(path, encoding="utf-8").read()
    lines = text.split("\n")
    newpos = [(m.start(), m.group(1)) for m in re_new.finditer(text)]
    funcs  = [(m.start(), m.group(1)) for m in re_func.finditer(text)]
    sa = lambda p: next((s for off, s in newpos if p >= off), None)
    fa = lambda p: next((nm for off, nm in funcs if p >= off), None)
    for m in re_out.finditer(text):
        go, cf = m.group(1), m.group(2)
        if go in NESTED: continue
        allm.append(dict(file=name, func=fa(m.start()), struct=sa(m.start()),
                         dir="Out", go=go, cfield=cf, cmt=cmt(cf)))
    for lnno, line in enumerate(lines):
        for m in re_in.finditer(line):
            cf = m.group(1); rest = line[m.end():]
            gos = re.findall(r'M(' + KOR + r')', rest)
            if gos:
                allm.append(dict(file=name, func=fa(m.start()), struct=None,
                                 dir="In", go=gos[-1], cfield=cf, cmt=cmt(cf)))

# -- 3) 한글 bigram 유사도 산출 (검토 우선순위용) --
def dice(a, b):
    def bg(s): return set(s[i:i+2] for i in range(len(s)-1)) if len(s) > 1 else set()
    A, B = bg(a), bg(b)
    return 2*len(A&B)/(len(A)+len(B)) if A and B else 0
ng = lambda g: re.sub(r'^M','',g).replace("_","")
for e in allm:
    if e["dir"] == "Out" and e["cmt"]:
        e["_sim"] = dice(ng(e["go"]), e["cmt"])

low = sorted([(e["_sim"], e) for e in allm
              if e["dir"] == "Out" and e.get("_sim", 1) >= 0 and e["_sim"] < 0.55],
             key=lambda x: x[0])
print("총매핑", len(allm), " OutBlock", sum(1 for e in allm if e['dir']=='Out'),
      " InBlock", sum(1 for e in allm if e['dir']=='In'))
for s, e in low:
    print(f"  {s:.2f} [{e['func']}] {e['go']} <- g.{e['cfield']} // {e['cmt']}  ({e['file']})")
```

## 6. 결과 판정 기준

산출된 유사도 목록을 검토할 때 아래 **실결함**과 **착시(버그 아님)**를 구분한다.

### 6.1 실결함 (등재 대상)
- Go 필드의 의미와 C 필드 주석 의미가 **완전히 다른 경우**
  - 예: `시가시각`/`고가시각` 필드에 `High`/`Low`(가)가 들어가야 할 곳에 `Opentime`(시가시간)이 들어가던 경우
  - `s.M<필드> = ... g.<다른역할필드>` 형태

### 6.2 착시 / 의도됨 (버그가 아님) — 제외
| 유형 | 예시 | 설명 |
|---|---|---|
| 어휘 차이 | `종목코드`←`Shcode`(단축코드), `매도_매수_구분`←`BnsTpCode`(매매구분) | Go 필드가 더 구체적. 의미는 동일 |
| 배열 생성자 | `s.M매도_거래원_정보_모음 = []string{ g.Offerno1, ... }` | 정규식이 컨테이너 이름만 캡처. 실제 요소 매핑은 올바름 |
| 문장 경계 크로스매칭 | `s.M일자 =당일.G값()` 다음 줄 `g.Hname`과 짝지어 `일자←Hname`으로 표시 | `g.Hname`은 `종목명` 할당. 별개의 문장 |
| 동일 필드 재사용 | `T0425` 연속키←`Ordno`, `T1902` 연속키←`Time` | 입출력 모두 동일 C필드 사용. TR 레이아웃 특수 |
| InBlock 질의값 캡처 | `질의값.` 등 이상 토큰 | InBlock 소스 추출 시착 |

**판정 최종 절차**: 유사도가 낮은 항목은 반드시 해당 `tr_*.go`의 실제 코드를 열어
`g.<필드>`가 어디에 할당되는지 확인한 후 결론 내린다.
